# 回归验证清单（已解决问题保护）

**基线**：v1.3.0（2026-08-08）。每次改动后对照本清单验证，确保不回归。

**用法**：改动方案/皮肤/数据后，逐项检查。任何一项不通过 = 改动破坏旧功能，需回退或修复。

**v1.3 现状（读清单前先知道）**：
- 词组表**只有简码行**（每字前 4 笔），**没有全码行**（v1.2 起删）
- schema `filters:` **只有 `uniquifier`**，**没有 `single_char_filter`**（v1.3 移除，它管不到前缀联想段）
- 词组只收 **2~4 字**（`PHRASE_MAX_LEN = 4`），且编码 **≥4 笔**（`PHRASE_MIN_CODE_LEN = 4`）
- 高频字有 **1/2/3 笔简码**（1,017 条），这是「3 笔进第一页」的唯一实现手段
- **升级 v1.3 必须清空用户词典**（简码 + 造词公式都变了）

## 四、冷启动候选排名（v1.3 新增，P0-1 保护）

**为什么单列一节**：这组问题只在**空用户词典**下暴露。用过几天的机器上用户词典会把常用字顶上来，掩盖回归。真机复测必须干净重装 + 清空用户词典。

| # | 已解决问题 | 验证方法 |
|---|---|---|

| 31 | 3 笔命中率无回归防线（改词库/权重悄悄变差） | `validate.py` 六段下限：1-100 ≥93%、1-300 ≥84%、1-600 ≥68%、1-1000 ≥54%、1001-2000 ≥11%、2001-3500 ≥4% |

**已知告警（不是回归，不要去"修"）**：
- 最/都/日/可 3 笔进不了第一页 — 撞在最拥挤前缀（szh/hsh/hsz），组合无解，`validate.py` 允许 4 个
- 「林」打满全码 `hspnhspn` 排 18 — 同码 17 个词组词频确实更高；`hsp` 简码排 7，用户不走全码路径
- 26 个 ≤3 笔编码上的精确匹配超过一页 — 该码最低频的 2-3 条落第二页，属容量上限
- 1-600 段命中率 71% vs 天花板 73% — 差值是 #34 留位规则的代价，不可两全
