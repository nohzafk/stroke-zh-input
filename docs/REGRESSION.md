# 回归验证清单（已解决问题保护）

**基线**：v1.4.0（2026-08-17）。每次改动后对照本清单验证，确保不回归。

**用法**：改动方案/皮肤/数据后，逐项检查。任何一项不通过 = 改动破坏旧功能，需回退或修复。 改皮肤前先读 `docs/SKIN_MODIFICATION.md`（操作规程：最小侵入/基线/md5 铁律/事故史）。改编码方案前先读 `docs/DESIGN.md §8`（v1.4 视觉块），改完必跑 `typing_test.py`。

**v1.4 现状（读清单前先知道）**：
- 词组表**只有自然码连续串行**（每字自然码：首部件 3~5 笔打全/独体前 4 笔），**没有全码行**
- 词组编码 = 每字自然码**连续拼接**（我们 = `phshpsnsz`，我 4 笔+们 5 笔），**不是** v1.3 的每字 4 笔
- 词组只收 **2~4 字**（`PHRASE_MAX_LEN = 4`），编码 **≥6 笔**（`PHRASE_MIN_CODE_LEN = 6`；4-5 笔词组默认不收 = librime remaining 机制，**A 方案例外**：jieba 词频 ≥10000 的超高频词放行，见 DESIGN §8.4）；6-7 笔词组权重 ×0.001（放行词除外）
- 单字有 **1~7 笔简码**（`SHORTCODE_LEVELS = (1..7)`，16,216 条），任意笔数精确匹配
- 自动造词走**公式 4 笔制**（stem = 全码），与自然码词库并存
- **升级 v1.4 必须清空用户词典**（编码体系从每字 4 笔变自然码）

**为什么单列一节**：这组问题只在**空用户词典**下暴露。用过几天的机器上用户词典会把常用字顶上来，掩盖回归。真机复测必须干净重装 + 清空用户词典。

**已知告警（不是回归，不要去"修"）**：
- 最/都/日/可 3 笔进不了第一页 — 撞在最拥挤前缀（szh/hsh/hsz），组合无解，`validate.py` 允许 4 个
